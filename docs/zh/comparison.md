# 与同类项目的比较

这里比较的是设计取舍，不是榜单。其他项目的描述以写作时的公开文档为准。

shm_pubsub 故意做得很小：每个区域一个 topic，固定大小的块，只支持 Linux。它适合放进现有的 C++11 工程，不引入新的工具链、守护进程或库内线程（`EventfdBridge` 是显式启动的集成线程）。它也是把 `SIGKILL` 之后的行为写成文档并用故障点测过的那一个。

| | shm_pubsub 0.4 | iceoryx2 | eCAL |
|---|---|---|---|
| 集成 | C++11 头文件，另有 C API 和 Python ctypes | Rust 核心，C/C++ 绑定 | C++ 库和工具 |
| 守护进程 | 无 | 无 | 无，但进程里有注册线程 |
| 范围 | 一台 Linux 主机 | 一台主机，多个操作系统 | 共享内存、UDP、TCP，可跨主机 |
| 载荷 | 固定块，可选大块类，零拷贝 | 零拷贝，动态尺寸 | 通常序列化 |
| 广播和竞争消费者 | 同一个 topic 里的私有队列和组 | 发布订阅为主，另有其他模式 | 不同的传输 |
| 背压 | 丢最新、丢最旧、组可阻塞；小块池按预算不会耗尽 | 可配置历史和缓冲 | 随传输变化 |
| 死亡进程 | 槽回收、本地修复、`recover()`，每个故障点都测过 | 死亡节点检测 | 不共享所有权 |
| 至少一次 | 组策略，带投递次数和死信 | 见其文档 | 见其文档 |

更完整的英文对照表在 [../comparison.md](../comparison.md)。

需要多操作系统、请求/响应或类型化服务模型时，iceoryx2 更完整。需要跨主机和现成的监控工具时，用 eCAL。
