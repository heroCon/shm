# 无锁设计

数据路径不拿互斥锁。发布、贷款、取走和释放都由原子操作和每个槽上的活动字组成。`collect_garbage()` 和 `recover()` 在调用进程里拿一把进程内的互斥锁，避免两个线程同时修同一块区域；self-heal 用 `try_lock`，拿不到就跳过。

队列是有界 MPMC：预留用 CAS 推进 `enqueue_pos`，提交把单元的序号从“位置”改成“位置+1”。取走同样用 CAS 声明队头。墓碑是读者会跳过的已提交单元。

发布者在投递期间把目标订阅者的位写进自己的 `pinned` 掩码，然后做一次顺序栅栏并再确认目标仍是活跃的。回收者把槽改成 `RECLAIMING` 之后做栅栏，并等到没有活发布者的掩码还指着这个槽。因此回收不会和正在入队的发布者交叉。

组的 `kBlock` 在操作之外等待空位，发布者此时不钉住任何槽，所以它睡着不会挡住回收。

块的引用字把“谁持有”和“有多少队列引用”放在同一个原子里，转换和释放都是一次 RMW，崩溃只可能留下多算的引用，不会留下算不清的中间态。多算的引用由重算或 `recover()` 收回。
